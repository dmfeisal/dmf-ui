# M10: preset completeness from recorded sources

Completed 13 November 2026. Planned in the [roadmap](DMF-UI-ROADMAP.md) (dmfeisal/dmf-ui#11) and shipped in dmfeisal/dmf-ui#12. No package version changed and nothing was packed.

## Audit

None of CB UI, HUI or QDI has a dark-mode source:

- CB's recovered token file has a `dark` colour role, but no dark theme.
- The HUI and QDI brand books record no dark mode.

Dark variants would be new design, not reconstruction, so the owner chose to close only what the sources support.

## What shipped

- **HUI Black headline weight**
  - Adds `src/assets/fonts/hui/mplus-rounded-latin-900.woff2` from `@fontsource/m-plus-rounded-1c@5.2.8`.
  - Provenance check: that package's 500 and 700 files are byte-identical to the ones already shipped. The OFL licence and notices already covered the family.
  - The `@font-face` is generated by `scripts/design-tokens.mjs`.
- **Only `h1` defaults to 900.** `brands.json` records the HUI headline as Rounded Mplus Black and the subheadline as Medium. Mapping the subheadline to specific heading levels would be a guess, so it is not done.
- **The rule's specificity is 0,0,2.**
  - DMF UI's scoped heading reset (`h1 { font-weight: inherit }` inside `@scope (.dmf-ui)`) is unlayered, so a base-layer rule had no effect.
  - At 0,0,2 the default beats that reset but still loses to weight utilities and Block styles. DMF UI emits those unlayered inside the same scope.
- **Explicit light-only records.** CB gains a "No dark-mode source; … light-only" gap, and HUI and QDI use the same wording. The closed HUI font gap now says what remains: Latin-only coverage.
- **Corrected docs.**
  - The CB and HUI preset pages no longer describe dark or black primary labels. They state the white owner-preference label and its recorded ratio (about 2.57:1 and 4.29:1) as a contrast exception.
  - The foundations record and the docs site's brand-mapping text match.
- **Drift check.** `tests/preset-records.test.mjs` fails if:
  - a preset doc contradicts `actionTextPolicy` or omits its ratio
  - a light-only preset lacks its no-dark-mode gap or shows dark usage
  - HUI loses its 900 face or its `h1` default
  
  The previous CB and HUI wording would have failed it. The package and token tests also cover the new WOFF2 and its signature.

## Not covered

- **Dark palettes for CB UI, HUI or QDI.** They would need new source material or a decision to design them as new work.
- **A complete CB specification.** It needs an original source.
- **HUI spacing, radius and application state scales.** The brand book has none.
- **HUI subheadline mapping.** Rounded Mplus Medium is not assigned to heading levels.
- **Packing.** M10 packed nothing. The new font changed `dmf-ui`'s shipped files, so `dmf-ui` 0.6.0 carries it to dmf-web. `@dmf-ui/core` 0.1.0 has never been given to a consumer, so its version stays until its first recorded archive.
- **Manual backlog unchanged.** Safari, Firefox, real devices and spoken screen readers remain on it.
